# 全站交互与蓝线规则

更新时间：2026-08-20（Asia/Shanghai）

本文件是 `portfolio-local-preview` 后续进行交互、动效和视觉反馈修改前的必读规则。它优先约束新的动效方案；如果历史原型与本文件冲突，以本文件和用户最新确认意见为准。

## 1. 总体方向

- 页面是纸张、手绘线条、人物和产品判断叙事组成的个人作品集。
- 动效的目标是让页面对读者的注意力做出回应，不是把页面做成炫技展厅。
- 统一交互语法：默认安静，靠近时回应，悬停时预览，点击时锁定或进入下一页。
- 动效要有明确原因：路径叙事、状态反馈、内容关联或跳转确认。不能为了“看起来有动效”而增加循环动画。
- 本轮只验收桌面网页。移动端交互只记录为后续任务，不在当前桌面交互实现中顺带处理。

## 2. 蓝线视觉硬规则

### 2.1 统一粗细

- 全页面承担路径、连接、引导作用的蓝线使用同一套视觉粗细。
- 当前项目区的细蓝线是基准，收尾区不能再使用明显更粗的蓝线。
- 收尾区的蓝线需要从当前约 `5px` 降到与项目区接近的视觉粗细；最终数值以桌面目标尺寸的视觉校准为准。
- 蓝线可以通过透明度和圆点强调层次，不能通过单独加粗某一区域解决层次问题。
- 小圆点可以比蓝线更醒目，但醒目来自圆点面积、填充、呼吸和短暂弹跳，不来自蓝线加粗。

### 2.2 路径必须服从母版坐标

- 项目区蓝线路径必须按照已确认的母版图坐标绘制，不能用通用 CSS 曲线、临时百分比路径或凭视觉重新画一条相似的线。
- 当前项目母版基准：
  - `当前使用/视觉母版/works-open-fields-master-v1.png`
  - `assets/illustrations/works/route-master-exact-v1.png`
- 网页运行时应把蓝线路径作为独立的 SVG 路径层或等价的真实路径数据层处理。项目插画、文字和蓝线继续分层。
- CSS 只能控制路径的表现，例如透明度、线宽、虚线绘制、状态过渡和轻微反馈；CSS 不能重新发明路径几何。
- 如果需要拆分路径、添加节点或让小圆点沿路径运动，所有新增路径段都必须从母版路径坐标中拆解或校准，不能改变原始构图关系。
- 蓝线不能跟随滚动进度，也不能变成鼠标轨迹。项目区蓝线进入视野后一次性完成主路径绘制，之后只允许发生局部 hover 反馈。
- 01 角色概览区的蓝线和蓝色物件也遵循同一套路径语言：黑白插画静态保留，蓝色路径、线团、节点使用独立 SVG 层产生低频流动、节点呼吸和 hover 强调。
- 01 区的 SVG 蓝线路径使用角色母版的 `1671 × 430` 坐标系；CSS 只控制绘制节奏、透明度和状态，不重新发明路径几何。
- 01 的蓝线仍按角色母版坐标绘制，但表现层要与黑色插画产生穿插关系：黑色图形可以在视觉上打断蓝线，不能让蓝线像贴纸一样始终浮在最上层。
- 01 右端不保留问号下方的黑色刷痕或水墨纹理，终点只使用干净的蓝色开放回路和蓝色引导点。

### 2.3 禁止的视觉隐喻

- 不使用水墨画、水墨晕染、墨水滴落、蓝色墨水滴落或类似“墨水扩散”的概念。
- 小圆点的概念是“蓝色引导点 / 路径节点 / 关注点”，不是墨滴、颜料或水滴。
- 不用毛玻璃、发光渐变、粒子爆炸或通用科技光效替代手绘线条语言。

## 3. 蓝色小圆点规则

- 小圆点是全站共享的交互角色，原则上同一时刻只允许一个点处于活跃状态。
- 项目区主蓝线完成后，小圆点可以停留在路径末端或当前节点，保持低幅度呼吸。
- 读者停留在某个项目卡附近时，小圆点可以从主线路径移动到当前项目附近。
- 小圆点沿项目插画的局部外缘滚动一小段，最后在项目标题或项目节点旁轻微弹一下。
- 项目区同一时刻只显示一个共享蓝点；项目节点可以保留在 SVG 中作为几何锚点，但不得与共享蓝点同时显形。
- 不让小圆点完整绕项目卡循环，不让四个项目同时各自拥有一个循环小圆点，也不让小圆点持续追踪鼠标。
- 小圆点的进入、停留、离开都必须服务于当前项目的关注反馈。
- 推荐的运动节奏：进入约 450 至 650ms，抵达后 1 次轻微弹跳，离开约 500ms。快速掠过项目时可以中断，不必每次完整播放。
- 键盘 focus 状态需要复用 hover 的项目强调逻辑；支持 reduced motion 时，小圆点改为静态停留在对应节点，不播放路径移动。

## 4. Works 项目区

- 项目卡的核心行为是点击后直接进入项目详情页，不使用项目抽屉作为主要路径。
- hover 只做预览，不打开详情，不改变页面结构：
  - 当前项目插画轻微抬起或放大；
  - 对应蓝线节点亮起；
  - 标题得到蓝色或轻微位移反馈；
  - 小圆点沿项目边缘短距离移动并弹一下；
  - 蓝点抵达项目附近时，项目条目做一次很轻的横向触碰反馈，提示这里可 hover 或点击；
  - 其他项目只轻微降低对比度。
- 项目图形、蓝线节点、项目标题必须同步回应，不能只让标题变蓝。
- 点击时小圆点可以短暂停在当前项目节点，随后直接跳转。不得为了等待动效而明显延迟跳转。
- 项目蓝线的主路径继续一次性绘制完成，不能改为跟随滚动或鼠标实时绘制。

## 5. About 区

- 三个问题不改成游戏化步骤，也不新增复杂抽屉。
- 三个问题共用一个蓝色引导点，不保留三个同时可见的静态蓝点；默认停在第一条，hover / focus 时移动到当前条目，点击后锁定当前位置。
- hover 或 focus 某个问题时，右侧问题和左侧正文中对应的语句同步强调：
  - “人真的会这样用吗？”对应真实的人和场景；
  - “到底是哪里不顺？”对应哪里不顺、为什么不顺；
  - “做出来以后呢？”对应有没有真的让体验好一点。
- 可以增加一条极细的蓝色关联线或短标记，表达左右内容的对应关系。
- 点击可以锁定当前问题；离开后未锁定的状态恢复安静。

## 6. 收尾与数字分身

- 收尾小圆点的“路径引导”概念保留，它是全站蓝点交互的参考来源。
- 收尾小圆点锚定在两只手的连接位置原地呼吸，不沿整条收尾路径漂到右下角；收尾路径只承担连接关系，不再承担第二个循环导览点。
- 收尾蓝线必须先完成统一线宽校准，再决定是否增加更多交互。
- 数字分身是否单独绘制图案尚未确认，不得先行生成或接入一张没有功能职责的静态人物图。
- 只有当图案能够承担明确状态时才考虑单独绘制，例如等待、倾听、思考、回答；如果只是装饰，不新增图案。
- 如果数字分身后端尚未接入，不能用静态人物图制造“已经可以真实对话”的错误预期。

## 7. 后续执行前检查

每次修改交互前，先确认：

1. 是否读过本文件、`当前使用/README.md` 和 `当前使用/确认文案.md`。
2. 是否仍然使用母版坐标，而不是重新画一条相似蓝线。
3. 是否保持蓝线统一粗细。
4. 是否把小圆点当作引导节点，而不是水墨或装饰粒子。
5. 是否只有当前被关注的项目在动。
6. 是否保留项目卡直接跳转路径。
7. 是否没有顺带修改移动端。
8. 是否为 reduced motion 保留静态反馈。
